# 约球 Web 应用 PRD（方案 B）

## 1. 文档信息
- 文档日期：2026-04-16
- 文档版本：V1.0
- 产品名称：约球（Web）
- 方案选择：B（约局广场 + 规则推荐）
- 发布目标：MVP 内测版本

## 2. 产品目标
围绕“更快成局、减少爽约、提升复约”，提供从发起约局到开打反馈的完整闭环。

### 2.1 北极星指标
- 7 日内成功开打场次

### 2.2 MVP 目标指标（上线后 8 周）
- 成局率 >= 45%
- 申请到通过转化率 >= 55%
- 爽约率 <= 15%
- 首次成局时间中位数 <= 24 小时
- 次周复约率 >= 25%

## 3. 目标用户
- 城市业余球友（18-40 岁）
- 下班/周末临时约球用户
- 希望匹配同水平、同区域球友的轻竞技用户

## 4. 核心场景
- 场景 A：用户今晚想打球，30 分钟内发布约局并招满人
- 场景 B：用户浏览附近约局，快速加入并确认开打
- 场景 C：主理人遇到临时退出，系统推荐替补用户补位

## 5. 范围定义

### 5.1 In Scope（MVP 必做）
- 登录与账号：手机号验证码登录（后续可扩展微信）
- 约局发布：时间、地点、人数、水平、费用说明
- 约局发现：列表、筛选、排序
- 申请加入：申请、审核、通过/拒绝
- 局内聊天：文本消息与系统消息
- 通知提醒：申请结果、开打前提醒、改期通知
- 规则推荐（方案 B 核心）：
  - 给参与者推荐“适合加入的约局”
  - 给主理人推荐“适合补位的球友”
- 履约反馈：赛后评价、爽约标记、举报入口

### 5.2 Out of Scope（MVP 不做）
- 复杂支付与自动分账
- 联赛系统与完整积分体系
- 多运动深度规则引擎
- 场馆管理后台 SaaS

## 6. 用户故事（MVP）
1. 作为发起者，我希望 1 分钟内发布约局，让附近合适的人尽快看到。
2. 作为参与者，我希望按时间/距离/水平筛选，快速找到适合我的局。
3. 作为发起者，我希望在有人申请时快速判断是否通过，避免沟通成本。
4. 作为参与者，我希望在通过后能在局内沟通细节并收到开打提醒。
5. 作为平台，我希望识别爽约行为并降低其后续匹配优先级，提升整体履约率。

## 7. 方案 B 功能需求

### 7.1 P0（首发必须）
- 账号与登录
  - 手机号 + 验证码登录
  - 基础个人信息：昵称、城市、默认水平
- 约局发布
  - 必填：时间、球馆/地点、人数上限、水平区间
  - 选填：费用说明、备注、是否接受新手
  - 规则：开打时间需晚于当前时间 30 分钟
- 约局广场
  - 列表展示：时间、地点、剩余席位、主理人信用分
  - 筛选：距离、时间、水平、是否可直接加入
  - 排序：优先展示“即将开始 + 距离近 + 成局概率高”
- 申请与审核
  - 申请状态：待处理/通过/拒绝/取消
  - 主理人 30 分钟未处理提醒一次
- 局内聊天与通知
  - 文本消息 + 系统消息（通过、拒绝、改期）
  - 开打前 2 小时和 30 分钟提醒
- 履约反馈
  - 赛后互评：1-5 分 + 标签
  - 爽约标记与申诉入口

### 7.2 P1（MVP+）
- 一键改期（保留原成员优先确认）
- 黑名单与举报处理流
- 主理人模板约局（复用历史配置）

### 7.3 P2（后续）
- 个性化推荐模型（从规则推荐升级）
- 场馆合作档期同步
- 成就与等级体系

## 8. 规则推荐设计（方案 B 核心）

### 8.1 推荐目标
- 提高成局率
- 缩短成局时间
- 降低爽约风险

### 8.2 约局推荐给用户（Join 推荐）
综合评分 = 距离分 + 时间分 + 水平匹配分 + 信用分 + 活跃度分

- 距离分：同商圈 > 同区 > 跨区
- 时间分：开打时间越接近用户可参与窗口，分值越高
- 水平匹配分：用户水平落在约局区间内得高分
- 信用分：低爽约用户优先看到高质量局

### 8.3 球友推荐给主理人（Fill 推荐）
综合评分 = 水平匹配 + 历史履约 + 距离 + 响应速度

- 展示前 10 位候选补位用户
- 主理人可一键邀请，用户收到“补位邀请”通知

### 8.4 推荐策略约束
- 不向被拉黑双方互相推荐
- 近期爽约高风险用户降权
- 同一用户在短时间内不过度重复曝光同一约局

## 9. 页面与信息架构
- 首页（推荐约局）
- 约局广场（筛选 + 列表）
- 约局详情（申请、成员、规则、聊天入口）
- 创建约局
- 消息中心
- 我的约局（发起/参与）
- 个人主页（信用、历史场次、评价）

## 10. 关键业务规则
- 信用分初始 100，爽约扣分，按月可小幅恢复
- 连续爽约 2 次：限制发局 7 天
- 连续爽约 3 次：限制发局与加局 15 天
- 评价仅限同一约局成员互评，开打后 24 小时内可提交
- 主理人取消约局需填写原因并触发全员通知

## 11. 数据埋点与看板

### 11.1 漏斗埋点
- 约局曝光 -> 点击详情 -> 申请加入 -> 通过 -> 到场确认 -> 赛后评价

### 11.2 推荐效果埋点
- 推荐位曝光
- 推荐点击率（CTR）
- 推荐促成申请率
- 推荐促成成局率

### 11.3 质量埋点
- 爽约率
- 改期率
- 举报率

## 12. 非功能需求
- 性能：移动端首屏 <= 2 秒（4G）
- 可用性：核心路径失败率 < 1%
- 安全：接口鉴权、频控、防刷、敏感词过滤
- 兼容性：主流移动浏览器可用（微信内置浏览器优先）

## 13. 验收标准（MVP）
1. 用户可完成：登录 -> 发局 -> 审核 -> 聊天 -> 开打 -> 评价完整流程。
2. 推荐模块可用并可配置规则权重。
3. 关键通知在触发后 1 分钟内到达站内消息。
4. 爽约标记、申诉、举报可形成后台可追踪闭环。
5. 数据看板可查看成局漏斗与推荐效果指标。

## 14. 里程碑与排期建议（5 周）
- 第 1 周：PRD 冻结 + 原型 + 技术方案
- 第 2-3 周：P0 开发联调
- 第 4 周：灰度内测 + 指标校验 + 问题修复
- 第 5 周：小流量上线 + 数据复盘 + P1 排期

## 15. 当前默认决策（可调整）
- 仅支持乒乓球（MVP）
- 默认“主理人审核”，可切换自动通过
- MVP 阶段不做线上支付，先线下 AA
- 优先移动端 Web 体验，桌面端提供基础可用
